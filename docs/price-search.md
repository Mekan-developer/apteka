# Поиск дешёвых аптек по Excel-прайсам — контекст и план

Этот файл — постоянный контекст для разработки модуля. Перед каждым этапом читай его целиком.
Работаем строго поэтапно: делай только тот этап, который назван в задаче, и останавливайся.

## 1. Что строим

Раз в неделю админ загружает один Excel-файл (.xlsx). **Каждый лист = отдельная аптека (поставщик)**,
название аптеки = название листа. Пользователь вводит название препарата («Цитрамон») и по кнопке
получает **топ-3 аптеки, где этот препарат дешевле всего**.

Реальный пример файла: `tests/fixtures/prices/sample.xlsx` — 98 листов, ~25 000 строк.
(Файл с реальными ценами поставщиков — в `.gitignore`; для тестов делаем урезанные фикстуры.)

## 2. Как устроены листы (проверено на реальном файле)

Форматы у всех разные, ручная чистка не предполагается — всё разбирается автоматически при загрузке.

**Шапка и колонки**
- Строка заголовка НЕ первая: сверху 1–6 строк мусора (название фирмы, телефоны, дата, «ПРАЙС ЛИСТ»).
- Бывает двухстрочный заголовок («Наименование» / « продукта» на следующей строке).
- Колонка названия подписана по-разному: «Наименование», «Наименования», «Ady/Наименование», «Описание»,
  «НОВОЕ ПОСТУПЛЕНИЕ», «Новое поступление 19.10.2026г.», «Ценовая группа/ Номенклатура/ …», или без заголовка.
- Колонка цены: «Цена», «цена», «Цена ТМ», «Цена в ТМ», «TMT Manat», «цена в ман», «Цена нал.», «Цена, нал.».
- Бывает несколько колонок цены: «Цена ТМ» + «Цена со скидкой -5%»; «Цена, нал.» + «Цена, переч.».
  Основная цена — без слов «со скидкой» / «переч.»; цену со скидкой сохраняем отдельно, если есть.
- Другие колонки (игнорируем или сохраняем как доп. инфо): №, ед. изм., кол-во в коробке, срок годности,
  производитель/страна, товарная скидка, нагрузка.

**Значения**
- Цена может быть текстом: `"2,50 man."`, `"55,00m."`, `"2,30"`, `"1.1000000000000001"`.
- Срок годности часто хранится Excel-серийным числом (`46784`) — НЕ путать с ценой.
- Номер строки бывает с мусором: `"1.\xa0\xa0\xa0 "`.
- Строки-разделители внутри таблицы: «Индия», «ABBOTT», «Фиксаторы шеи:», «Новое поступление» — не товары
  (нет цены).
- Один и тот же товар может повторяться в листе дважды.

**Скидки — 4 вида**
1. Колонка у товара: «товарная скидка» = `0.03`, `0.05`, «10% товарный скидка», «без скидки».
2. В названии товара: «Акбар №100 (+ товар.скидка)», «… 15% Товарная скидка».
3. На весь лист отдельной строкой: «Товарная скидка 5%», «-5% Скидка!», «"5%" скидка при оплате наличными».
4. От суммы заказа, иногда лесенкой: «От суммы выше 10тыс манат финансовая скидка 5% на все»,
   «20 000 ман -2% скидка / 30 000 ман -3% …», «ПРИ ЗАКАЗЕ НА СУММУ ОТ 10000 МАНАТ- 5% ТОВАРНАЯ СКИДКА».

**Названия**
- Ошибки и варианты: «Аналгин» / «Анолгин» / «Аналгин 10мг»; «Цитрамон-Боримед таб №6» /
  «Цитрамон - Боримед таблетки 200мг №6 Беларусь» / «ЦИТРАМОН-П (бумажном/упаковке) таблетки № 6».
- Фасовка влияет на цену: «Цитрамон П №10» (2.6) vs «Цитрамон №6» (1.5) vs «ACTION PLUS (ЦИТРАМОН) №4» (1.1).
  Сравнивать цены можно только внутри одной фасовки (`№N`).
- Действующее вещество часто в скобках: «Ал-Панадол (Парацетамол)», «Регамол (парацетамол 500мг)».

## 3. Бизнес-правила (по умолчанию, пока заказчик не скажет иначе)

- Активна одна загрузка — последняя подтверждённая. Старые загрузки храним как историю, в поиске не участвуют.
- **Товарная скидка** (бонус товаром) из цены НЕ вычитается — показывается пометкой рядом с ценой.
- **Условная скидка от суммы** (вид 4) из цены НЕ вычитается — показывается пометкой «от 10 000 ман −5%».
- **Безусловная ценовая скидка на весь лист** (вид 3, не товарная) — считаем `effective_price`
  и сортируем по нему, но показываем и исходную цену.
- Результат поиска группируется по варианту препарата: форма выпуска + дозировка + фасовка
  («Азитромицин · 500 мг · таблетки · №3»), для каждого варианта — топ-3 аптеки по цене.
  Название без формы или дозы присоединяется к единственному подходящему варианту, иначе остаётся
  отдельным (`OfferGrouper`). Контакты аптеки (телефоны, адрес) читаются из строк над шапкой листа.
- Эти правила вынесены в одно место (сервис/конфиг), чтобы их легко поменять.

## 4. Технические правила проекта

- Стек: PHP 8.3, Laravel 13, Inertia v3 + Vue 3 + TypeScript, Tailwind 4, shadcn-vue (reka-ui), Wayfinder,
  Pest 4. БД: **PostgreSQL** (16+) — в Docker (dev/prod), в тестах и в CI. SQLite и MySQL больше не
  используем: поиск опирается на расширение `pg_trgm`, поэтому тесты тоже гоняются на PostgreSQL
  (отдельная тестовая база).
- Архитектура: Route → Controller → Service → Repository. Контроллеры тонкие, валидация в Form Request.
- Парсер — чистые PHP-классы без зависимости от БД и Laravel-фасадов, покрытые unit-тестами.
- Тяжёлая работа (разбор файла) — в очереди (Job), контейнер-воркер уже есть.
- Все тексты интерфейса — через переводы `lang/ru` и `lang/tk`.
- Уведомления пользователю — через существующий хелпер `notify()`.
- Маршруты на фронте — через Wayfinder.
- `preventLazyLoading` включён — всегда eager loading.
- Каждый этап заканчивается зелёными тестами: `php artisan test`, Larastan, Pint.
- Коммиты: автор — мой git config, **никаких** `Co-Authored-By`, `Claude-Session`, «Generated with Claude».

## 5. Модель данных (ориентир, уточняется на этапе 1)

- `pharmacies` — id, name (из названия листа, уникально), phone (nullable), timestamps.
- `price_uploads` — id, user_id, original_filename, stored_path, status
  (`uploaded|processing|needs_review|active|archived|failed`), sheets_total, sheets_ok, rows_total,
  activated_at, timestamps.
- `price_upload_sheets` — id, price_upload_id, pharmacy_id, sheet_name, sheet_index, status
  (`parsed|needs_review|skipped|failed`), header_row, name_col, price_col, price_discounted_col (nullable),
  rows_parsed, error (nullable), preview_json (первые ~10 сырых строк для экрана проверки).
- `pharmacy_sheet_mappings` — запомненная настройка колонок для аптеки: pharmacy_id, header_row,
  name_col, price_col, price_discounted_col, header_signature (хэш текста заголовка — если поменялся,
  маппинг не применяем автоматически).
- `price_items` — id, price_upload_id, pharmacy_id, raw_name, name_normalized, name_skeleton,
  base_name, active_ingredient (nullable), pack_count (nullable, из `№N`), dose (nullable),
  price (decimal 12,2), price_discounted (nullable), goods_discount_percent (nullable),
  discount_note (nullable), manufacturer (nullable), source_row. Индексы: btree (price_upload_id),
  GIN `gin_trgm_ops` на `name_normalized`, `base_name`, `active_ingredient`; btree на `name_skeleton`.
- `discount_rules` — id, price_upload_id, pharmacy_id, type (`price|goods`), percent, min_sum (nullable),
  raw_text.

## 6. Поиск (PostgreSQL + pg_trgm)

1. Нормализация (один класс `NameNormalizer`, используется и при импорте, и при поиске):
   нижний регистр, `ё→е`, латиница-двойники → кириллица там, где слово кириллическое, убрать пунктуацию,
   схлопнуть пробелы; выделить `pack_count` (`№ 6`, `N6`, `#6`), `dose` (`200мг`, `5 мл`, `1 гр`),
   действующее вещество из скобок; убрать слова формы (таб., таблетки, капс., р-р, сироп …) в `base_name`.
2. `name_skeleton` — только согласные, повторы схлопнуты («аналгин» и «анолгин» → `нлгн`) —
   дополнительный сигнал к триграммам для опечаток в гласных.
3. Расширение `pg_trgm` включается миграцией (`CREATE EXTENSION IF NOT EXISTS pg_trgm`).
4. Запрос — одним SQL в репозитории, только по активной загрузке:
   кандидаты через `word_similarity(:q, base_name)` / оператор `<%` по `base_name` и `active_ingredient`
   (+ совпадение по `name_skeleton`) с порогом (вынести в конфиг, стартово ~0.4) →
   score = максимум из похожестей → группировка по `pack_count` → в каждой группе минимальная
   цена на аптеку (`DISTINCT ON (pharmacy_id)` или оконная функция) → сортировка по
   `effective_price` → топ-3 в группе.
5. Если ничего не нашлось — подсказка «Возможно, вы имели в виду …» (топ-5 ближайших `base_name`).

## 7. Этапы

00. **Переход на PostgreSQL.** Заменить MySQL на PostgreSQL 16 в docker-compose (dev и prod),
   обновить `.env.example`, PHP-образ (расширение `pdo_pgsql`), `config/database.php` по умолчанию.
   Тесты — на отдельной PostgreSQL-базе (`phpunit.xml` / `.env.testing`), убрать SQLite.
   GitHub Actions — сервис `postgres` в `tests.yml`. Проверить, что все существующие миграции и
   тесты проходят. Если на проде уже есть данные в MySQL — сначала сказать мне, не переносить молча.
0. **Проверка чтения файла.** Выбрать библиотеку чтения (PhpSpreadsheet в режиме readDataOnly
   с загрузкой по одному листу или openspout/openspout — стриминг). Сделать artisan-команду
   `prices:inspect {path}`: список листов, число строк, первые 8 непустых строк каждого листа.
   Замерить память и время на `sample.xlsx`. Файл содержит нестандартные стили — проверить, что не падает.
1. **Модель данных.** Миграции (включая `pg_trgm` и GIN-индексы), модели, фабрики, связи, enum'ы
   статусов. Тесты на миграции/фабрики.
2. **Ядро парсера (без БД).** `HeaderDetector`, `PriceParser`, `RowClassifier`, `NameNormalizer`,
   `DiscountExtractor`, `SheetParser` (собирает всё вместе, возвращает DTO с результатом и статусом).
   Unit-тесты на массивах, взятых из реальных листов (Kamat, ASDS, Enejan, Gumry, Em dem, Tebip apt,
   Ashgabat, HayyrlyDerman, Rysgally el). Команда `prices:dry-run {path}` — отчёт по всем листам:
   сколько разобрано, какие `needs_review` и почему.
3. **Импорт.** Страница загрузки (Form Request: xlsx, лимит размера), сохранение файла,
   `ImportPriceUploadJob` в очереди: по листам, сначала применяет сохранённый маппинг аптеки, иначе
   автоопределение; пишет `price_upload_sheets`, `price_items`, `discount_rules`. Прогресс — поллинг
   статуса загрузки. Feature-тесты с урезанной фикстурой.
4. **Экран проверки.** Список листов загрузки со статусами; у листа — превью сырых строк, выпадающие
   списки «колонка названия / колонка цены / строка заголовка», кнопка «Переразобрать лист»
   (сохраняет маппинг для аптеки). Кнопка «Активировать загрузку» (предыдущая → archived).
5. **Поиск.** Сервис поиска по разделу 6, страница с полем поиска и карточками: аптека, точное
   название из прайса, фасовка, цена (и цена со скидкой), пометки о скидках, телефон. Тесты на
   «аналгин/анолгин», группировку по фасовке, топ-3, учёт только активной загрузки.
6. **Доводка.** Ручной справочник синонимов (`ACTION PLUS` → цитрамон), индексы и замеры скорости,
   история цен по препарату, переводы tk/ru.
